# GitHub 网络自检 · 使用说明

一个纯本地、零依赖的小工具：双击就跑，测完自动出一份 HTML 报告。
不安装任何软件，不读取你的账号，不向任何服务器上传数据。

## 怎么用

1. 双击 **一键网络自检.bat**
2. 弹出一个命令行窗口，逐个测试 11 个目标，大约 20～40 秒（看你网络差到什么程度）
3. 测完会先问你三句：「这次要生成 HTML 报告吗？」「要现在用浏览器打开吗？」「记住这次的选择吗（下次不再问）？」

   答「记住」就把这次的选择写进 `settings.json`，以后不再问；想改回来，进「设置」勾上「每次自检结束后先问我」。
   报告存在 `reports\`（`latest.html` 是最新一份，历史按时间戳各存一份 html + csv）。

4. 启动时会静默检查一次更新（只读一个公开版本号，3 秒超时，连不上就跳过）；设置里可以关掉，
   也可以从菜单 [5] 手动查。更新源默认 Gitee；设置里可锁定成「只用 Gitee」或「只用 GitHub」，
   只有语言不是中文、时区也不是 UTC+8 这种明确迹象才会自动改走 GitHub。

## 测的是什么

每个目标按顺序测四段，分别计时，能精确定位卡在哪一步：

| 阶段 | 含义 | 失败说明 |
|---|---|---|
| DNS | 域名解析耗时 | 解析不出来 = DNS 污染或断网 |
| TCP | 到 443 端口的建连耗时 | 超时 = 端口不通，多半被阻断 |
| TLS | 加密握手耗时 | 超时/被重置 = SNI 干扰，典型的表现就是"网站打不开但 ping 通" |
| HTTP | 发出请求到收到首字节 | 超时 = 链路被掐断 |

## 专门给 AI Agent 场景加的专项点位

网页能打开，不代表 Agent 能拉代码；反过来也一样。所以这几条是分开测的：

| 点位 | 用途 | 挂了会怎样 |
|---|---|---|
| GitHub API 接口 `api.github.com/rate_limit` | Agent 查仓库、拉元数据，顺带读出当前配额 | Agent 调不了 API |
| GitHub Raw 原始文件 `raw.githubusercontent.com` | Agent 直接读取仓库里的文件内容 | 读文件被重置，Agent 拿不到源码 |
| GitHub Git 传输 `github.com/.../info/refs` | git clone / pull 真正走的通道 | 克隆失败，但网页可能还能正常开 |
| GitHub 仓库打包 `codeload.github.com` | 下载仓库 zip / tar | 一键下载整仓库失败 |
| GitHub Gist `gist.githubusercontent.com` | 读代码片段、配置 | 读 gist 失败 |

报告顶部会显示 **API 配额**（未登录时是 60 次/小时），Agent 频繁调接口被限流时可以看这个数字。
## 判读

| 标签 | 依据 | 说明 |
|---|---|---|
| 优秀 | 建连 ≤ 120 ms | 和国内站点差不多快 |
| 良好 | ≤ 400 ms | 正常可用 |
| 一般 | ≤ 1000 ms | 能用但会卡顿 |
| 较慢 | > 1000 ms | 几乎没法用 |
| 受限 | TCP 通、TLS 失败 | 最典型的"被墙"状态 |
| 不通 | TCP 都连不上 | 完全阻断 |

报告里的 **DoH 真实解析**：用阿里公共 DNS 加密查询拿到该域名的真实 IP，和本机解析结果对比。
两者不一致，说明本机 DNS 被改写或被污染；如果本机 IP 显示 `127.0.0.1`，说明域名被 hosts 接管了。

## 和瓦特工具箱是什么关系

瓦特工具箱（Watt Toolkit，原名 Steam++）的加速思路是：

```
hosts 把域名指向 127.0.0.1
      ↓
本机跑一个 YARP 反向代理（监听 80/443）
      ↓
反代用自己的线路去连真实服务器
      ↓
浏览器以为在直连，实际走的是本机反代（中间人，靠自签根证书解密）
```

这个工具的定位不一样：**它不代理，只测量**。
所以最实用的用法是——加速器关着跑一次，开着再跑一次，两份报告对比，立刻就能看出加速到底有没有生效、哪个域名还在掉。

需要注意两种模式下的差异：

- **hosts 模式**：域名解析到 127.0.0.1，报告里的 IP 会显示 127.0.0.1，测到的延迟其实是"你到本地反代"的延迟，不代表到真实服务器的速度
- **系统代理模式**：本工具用原生 socket 直连，不走系统代理，所以测到的仍是真实直连状况——这正好可以用来判断"如果不加速会有多惨"

## 进阶用法

```powershell
# 只测 GitHub 系（快一些）
powershell -ExecutionPolicy Bypass -File netcheck.ps1 -Quick

# 测完不询问、不打开浏览器，只按记住的「要不要报告」执行（给自动化/CI 用）
powershell -ExecutionPolicy Bypass -File netcheck.ps1 -NoBrowser
```

想换测试目标，用记事本打开 `netcheck.ps1`，改开头 `$Targets` 那段，照着格式加一行就行：

```powershell
@{ Name = '某个站点'; Host = 'example.com'; Desc = '备注' }
```

## 已知限制

- 测的是 TCP/TLS 握手延迟，**不等于下载速度**。要测带宽得另外传大文件。
- 只测 IPv4、TLS 1.2。
- 为了测纯网络连通性，证书校验被忽略。所以"证书链有问题但能连上"的情况，报告会显示正常。
- 超时统一 3 秒。网络特别差的时候，某些目标可能本来 5 秒能连上也被判失败——重跑一次看是否稳定即可。
- 每次运行都会在 `reports` 目录留一份 html 和 csv，觉得多了可以自己删。
