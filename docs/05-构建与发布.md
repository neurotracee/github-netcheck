# 构建与发布

## 一、环境

| 项 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17 | AGP 8.x 要求 JDK 17 |
| Gradle | 8.7 | AGP 8.4.2 要求 ≥ 8.6 |
| Android SDK Platform | 34 | `compileSdk = 34` |
| Android Build Tools | 34.0.0 | 由 SDK 自动选择 |
| Kotlin | 1.9.24 | |
| compileSdk / targetSdk / minSdk | 34 / 34 / 26 | minSdk 26 = Android 8.0 |

Windows 端不需要构建环境：只要 PowerShell 5.1+（Windows 10/11 自带）。

## 二、Windows 端「构建」

没有构建步骤。要分发的就是两个文本文件：

```
windows/netcheck.ps1
windows/一键网络自检.bat
```

打包成 zip 时把这两个放在同一层目录即可，`reports/` 会在首次运行时自己创建。
不要把 `reports/` 打进去（那是运行产物，且含你自己的解析结果）。

**发布前自检**：

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\netcheck.ps1 -NoBrowser
```

确认：14 个点位都跑完、`windows/reports/` 下生成了 html + csv、控制台最后打印了报告路径、没有红色报错。

## 三、安卓端构建

```bash
cd android
gradle assembleRelease
```

产物：`android/app/build/outputs/apk/release/app-release.apk`

### 关于中文路径

工程目录含中文时 AGP 会拒绝构建，`android/gradle.properties` 里已经加了：

```properties
android.overridePathCheck=true
```

这样能编出 APK。但**单元测试在中文路径下会全部报 `ClassNotFoundException`**
（Gradle 测试工作进程加载类路径时按系统默认编码处理中文目录名，JVM 侧解析不到）。
解决办法是把工程复制到纯英文路径再跑测试：

```powershell
robocopy android D:\android-build\NetCheck\testrun /E /XD build .gradle
gradle -p D:\android-build\NetCheck\testrun test
```

CI（GitHub Actions / Gitee Go）的检出路径本来就是纯英文，不受影响。
**APK 本身与路径无关**，`assembleRelease` 在中英文路径下产物一致。

### 签名

`android/app/build.gradle.kts` 读 `android/keystore.properties`：

```properties
storeFile=D:/android-build/NetCheck/netcheck-release.jks
storePassword=<你的密码>
keyAlias=netcheck
keyPassword=<你的密码>
```

第一次生成自己的密钥：

```bash
keytool -genkeypair -v \
  -keystore netcheck-release.jks \
  -alias netcheck -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <密码> -keypass <密码> \
  -dname "CN=NetCheck, OU=OpenSource, O=neurotracee, L=Datong, ST=Shanxi, C=CN"
```

**`*.jks` 与 `keystore.properties` 都在 `.gitignore` 里，不要提交。**
没有 `keystore.properties` 时构建不会失败，只是打出未签名的 release 包（`adb install` 会拒绝）。

## 四、产物核对（发版前必做）

```bash
# 包名 / 版本号 / SDK / 权限 / 标签
aapt2 dump badging app/build/outputs/apk/release/app-release.apk | head -20

# 签名是否有效
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

必须对上：

| 项 | 期望值 |
| --- | --- |
| package | `com.neurotracee.netcheck` |
| versionName | 与 CHANGELOG 顶部一致（如 `1.0.0.0`） |
| versionCode | 由 versionName 算出的数字（`1.0.0.0` → `1000000`） |
| sdkVersion | `26` |
| targetSdkVersion | `34` |
| uses-permission | 只有 `INTERNET` 与 `ACCESS_NETWORK_STATE`（另有一个 androidx 自动加的 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`，属正常） |
| 包体大小 | 约 9.5～10 MB（Compose 运行时占大头，没有 native 库） |

**不允许出现的权限**：存储、位置、通讯录、短信、相机、`REQUEST_INSTALL_PACKAGES`（本项目不做应用内更新）。

再验证一次「里面没有多余东西」：

```bash
unzip -l app-release.apk | grep -Ei "okhttp|retrofit|firebase|umeng|analytics"
```

应当无输出。APK 里也不该有 `lib/*.so`（纯 Kotlin 实现，无 native 依赖）。

## 五、版本号

只改一处：`android/app/build.gradle.kts` 的 `appVersionName`。

```kotlin
val appVersionName = "1.0.0.0"
```

`versionCode` 自动计算：`主*1000000 + 次*10000 + 修订*100 + 补丁`。
Windows 端同步改 `netcheck.ps1` 头注释里的版本号与报告页脚，并在 `CHANGELOG.md` 顶部加一节。

## 六、发布到两个平台

两个仓库内容完全一致，先推 GitHub 再推 Gitee（或反过来），**同一次提交、同一个 tag**。

```bash
# GitHub
git remote add github git@github.com:neurotracee/netcheck.git
git push github main
git push github --tags

# Gitee（镜像）
git remote add origin git@gitee.com:bio234/netcheck.git
git push origin main
git push origin --tags
```

Tag 命名与版本号一致：`v1.0.0.0`。

发布附件命名：

```
NetCheck-1.0.0.0.apk        # 安卓
NetCheck-Windows.zip        # Windows（含 netcheck.ps1 + 一键网络自检.bat + 使用说明.md）
```

**不要**在文件名里写死某个旧版本号的说明；README 里所有下载链接都指向 releases/latest。

Release 正文至少写清：

1. 一句话总结（≤100 字）；
2. 按平台分开的详细条目（Windows / 安卓）；
3. 校验值（APK 的 SHA-256）；
4. 已知问题（若有）。

一步步的网页操作见 [06-发布Release操作指南.md](06-发布Release操作指南.md)。

## 七、CI

`.github/workflows/ci.yml` 做两件事：

1. **安卓构建 + 单元测试**（`gradle assembleDebug test`），在纯英文路径下跑，避免中文路径的测试类加载问题；
2. **静态自查**：确认 APK/源码里没有引入第三方网络库、没有新增权限、没有统计 SDK 关键字。

CI 不发布产物，Release 由本地手动构建后上传——因为发布用的签名密钥不在仓库里。
